# 从线程到进程

## 1. 线程与进程的区别

在 Lab1 中，所有线程属于同一个进程，可以访问同一份 A、B、C。在 Lab4 中，`mpiexec` 启动多个程序进程，每个进程执行同一个程序，但保存和使用自己的数据。

| 问题 | OpenMP 线程 | 本实验的 MPI 进程 |
|---|---|---|
| 如何识别参与者？ | 线程编号。 | 通信组中的 rank。 |
| 如何读取其他参与者的数据？ | 在共享内存中按地址读取。 | 通过消息传递到本地缓冲区。 |
| 谁划分工作？ | OpenMP 循环调度或程序构造的任务。 | 程序明确划分 A、B 的行段。 |
| 运行在哪里？ | 同一进程所在的共享内存电脑。 | 可以在同一台电脑，也可以在多台主机。 |

## 2. rank 与 size

MPI 初始化后，可以查询当前通信组中的进程总数与自己的编号：

```cpp
MPI_Init(&argc, &argv);
MPI_Comm_rank(MPI_COMM_WORLD, &rank);
MPI_Comm_size(MPI_COMM_WORLD, &size);
```

`MPI_COMM_WORLD` 包含本次启动的进程，rank 从 0 开始。程序根据 rank 决定自己的数据范围，退出前调用 `MPI_Finalize()`。

打开 `src/main.cpp`，从初始化开始阅读。命令 `mpiexec -n 4 ...` 启动四个进程；它与 OpenMP 的四个线程是不同的运行模型。

## 3. 划分 A 的行

每个进程负责连续的一段 A 行，输出 C 中相同范围的行。这让各进程拥有互不重叠的输出区域。

`--partition rows` 根据行数划分，`--partition nnz` 根据累计非零数划分。它们都保留完整行，不把同一输出行拆给不同进程。

和 Lab1 一样，稀疏输入的“行数相同”不一定表示“乘加次数相同”。可以从 `src/distribution.cpp` 查看两种划分，并在输出的 `row_begin`、`row_end` 和 `nnz` 中找到对应信息。

## 4. 划分 B 的行

B 按连续行区间分布，各进程只持有其中一段。对于本地 A 中的每个列号 k：

```text
如果 B[k,:] 属于当前进程 → 本地读取
如果 B[k,:] 属于其他进程 → 需要通信
```

因此 **A 的列索引决定了对 B 的需求**。即使本地 A 的行段是连续的，引用的 B 行也可能遍布整个矩阵。

!!! tip "跟着一条非零元素读代码"
    找到它的全局行号 i 和列号 k，确定 C 的写入进程，再确定 B 的持有进程。这个过程能帮助你理解：为什么输出已经分开，仍然需要通信。

## 5. 两种完整 B 的获取方式

Broadcast 由 rank 0 提供完整 B，调用 `MPI_Bcast` 让参与进程得到它。Allgather 让各进程贡献自己持有的 B 行，调用 `MPI_Allgatherv` 收集到完整 B。

两者都让本地计算能按全局 k 直接读取 B，但数据提供者和通信组织不同。后面的按需交换，会利用 A 实际引用的 B 行集合来减少无关数据。

??? info "为什么 Allgatherv 最后有一个 v？"
    这里各进程拥有的 B 行数可能不同。`MPI_Allgatherv` 接收每个进程的元素数和放置位置，让不同长度的数据段放到目标缓冲区的相应位置。
